# Changelog

## [2.1.3] - 2026-11-09

### Fixed

- **修复 2.1.2 的手动缩放完全失效**：客户区被 WebView2 的子窗口盖住，主窗口的
  `WM_NCHITTEST` 在窗口边缘收不到鼠标调用，「系统原生缩放」实际上从未触发过。
  现在恢复 2.1.1 的做法——页面四边 / 四角放透明热区（z-index 高于标题栏），
  `mousedown` 调 `window_resize(edge)`，后台线程跟光标缩放（下限 480×360 × DPI），
  松手自动停。拖动和吸附仍是系统原生行为，不受影响。

## [2.1.2] - 2026-11-09

### Changed

- **吸附改为 Windows 原生行为**：不再由程序自己计算半屏 / 四分之一屏的位置、绘制预览块
  或逐帧移动窗口。标题栏拖动现在直接进入系统移动循环，边缘预览、落位动画、
  Win+方向键和 Win11 贴靠布局都交给 Windows 处理。
- **四边 / 四角缩放交给系统**：通过 `WM_NCHITTEST` 返回对应的边框命中值，
  删除主页面里的透明缩放手柄；鼠标光标、缩放过程和最小尺寸都与普通桌面程序一致。
- 最大化按钮返回 `HTMAXBUTTON`，支持 Win11 悬停贴靠布局；`WM_GETMINMAXINFO`
  将最大化范围限制在当前显示器工作区，避免盖住任务栏。
- 从托盘重新打开主窗口时保留吸附后的尺寸，不再强制恢复成 1180×830。

## [2.1.1] - 2026-11-09

### Changed

- **窗口可以缩得更小了**：最小尺寸从 900×620 降到 480×360，配合新的紧凑排版，
  缩到四分之一屏也不会出现横向滚动条或被裁掉的按钮。
- **接上 Windows 的窗口吸附**：Win+← / Win+→ 左右半屏、再按 Win+↑ 变成四分之一屏，
  或者直接把窗口拖到屏幕边缘 / 角落，都会像普通 Windows 程序一样吸附定位；
  拖动时贴边会出现半透明预览块，松手才落位。
- 小窗口（高度 ≤ 660px，即 1080p 的上半屏）自动进入紧凑模式：收起副标题和大标题、
  隐藏「当前焦点」卡片、压扁统计卡，让待办清单尽早露出来；高度 ≤ 470px 时再收一层。

### Fixed

- 窗口补上可缩放样式后，系统会给客户区留一圈约 10px 的边框（125%/150% 缩放下更明显），
  导致界面四周出现空边。现在接管 `WM_NCCALCSIZE`，客户区重新铺满整个窗口。

## [2.1.0] - 2026-11-08

### Added

- **OJ 支持挂多个站点，可以自己加、自己删**。以前只认一台 OJ（地址写死在
  `oj_client.py` 的 `DEFAULT_BASE`），换学期要么重装、要么改代码。现在登录框顶部是站点列表：
  「+ 添加站点」填地址 → 自动补 `http://`、认整条浏览器地址（`http://x/#/login` 也行）→
  点「检测并添加」，程序先向那台机器要一张验证码确认是同款 OJ，通了才存进配置。
- 每台站点独立登录、独立缓存：新加一台不影响已经在用的那台，删掉一台也不动其他站点和畅课。
  最多同时挂 6 台。
- **站点可以起名字**（如「26 秋 数据结构」），看板上直接显示，比记 IP 末段清楚。
- **看板上按站点区分**：多站点时 `OJ` 徽标变成 `OJ · 26 秋 数据结构`，三套配色循环，
  鼠标悬停看完整地址；OJ 板块标题右侧显示「2/3 个站点」，有站点连不上时额外标「1 个异常」。
- 顶栏 OJ 按钮在多站点时显示「OJ · 2/3」，部分站点掉线变橙、需要重新登录变红。
- 新增接口 `/api/oj/sites/add`、`/api/oj/sites/remove`、`/api/oj/sites/rename`；
  `/api/oj/captcha`、`/api/oj/login`、`/api/oj/logout` 都多了 `base` 参数。
  `/api/oj/base` 保留为「添加站点」的旧别名。

### Changed

- 条目 id 从 `oj-45` 变成 `oj-<站点 key>-45` —— 不同学期的 OJ 实验 id 会重复，同 id 会互相
  覆盖（勾了这台的实验，那台也跟着消失）。站点 key 由地址算哈希，删了再加回来还是同一个。
- `prefs.json` 里单个 `ojBase` 换成 `ojSites` 数组；`oj_session.dat` 从一条记录改成
  `{"sites": {base: record}}`。**升级时自动迁移，登录状态和已勾的完成记录都不丢**。
- 出厂默认站点如果从没登录过，添加新站点时会直接被顶替掉，不会凭空多出一个用不上的空站点。

### Notes

- **仍然只读**：只拉清单和得分，没有任何写操作。
- 一台连不上只降级它自己：那台这轮不显示，状态点变橙，其他站点和畅课的清单照常。

## [2.0.0] - 2026-11-08

### Added

- **接上校内 OJ，实验和畅课作业在一个列表里看**。OJ（`172.31.221.62`）上的实验会跟畅课的
  待办混排：逾期置顶、其余按截止时间升序，卡片左上角多一个绿色 `OJ` 徽标，课程名和类型
  （实验 / 作业）照常显示。不需要在两个网站之间来回切。
- **已经交过的实验保留 7 天，并显示判题得分**。卡片变成淡绿色、勾选框置灰，右侧直接显示
  `90 / 100` 这样的分数，比在 OJ 里一题题翻快得多。7 天后自动从列表消失。
- **OJ 登录入口**。顶栏账号按钮旁多了一个 `OJ` 状态按钮：绿点=已连接、橙点=当前离线（不在
  校内网）、红点=需要重新登录、灰点=还没配。点开就是登录框，验证码直接显示在窗口里。
- **过期没交的实验也会进「已逾期」**。OJ 上错过截止的实验会留在逾期分组里提醒，勾掉
  「已完成」才消失，和畅课的逾期作业一个逻辑。
- **两个来源左右分栏**。畅课和 OJ 都登录时，看板分成左右两栏（畅课在左、OJ 在右，
  约 1.08 : 0.92）；只登录一个时那一块铺满整幅，另一边留一句提示和登录按钮；
  窗口窄于 1080 px 自动退回上下排列。半栏宽度下卡片把「剩余时间 / 得分」挪到标题下方右对齐。

### Fixed

- **只登录 OJ、没登录畅课时，列表不再被整张登录卡盖住**。以前 `/api/homework` 因为畅课
  未登录直接返回 401，界面只剩「登录深大优课」和一张登录框，OJ 明明登着却一条也看不到。
  现在服务端会先把 OJ 那部分返回（用 `lmsAuth` 标记「畅课还差一次登录」），看板正常显示
  OJ 区块、畅课区块留登录按钮，并且不再自动弹登录框挡列表。
- OJ 的截止时间原来截到分钟（`23:59:59` 存成 `23:59`），倒计时和「已截止」判断会早 59 秒，
  现在精确到秒。
- 老师没设满分时（`total_score` 为 0），得分不再显示成 `91 / 0`，只显示 `91`。

### Changed

- 看板标题的计数变成「N 项待办 · M 项已交」，已交的那部分单独成组放在最下面。
- 底部那句安全说明补了一句：勾完成不会影响 OJ 的判题结果。

### Notes

- **版本号从 1.5.3 直接跳到 2.0.0**。作业源从一个变成两个，登录、缓存、布局都跟着改，
  属于结构性变更，所以不单发 1.6，直接进 2.0。
- **只读**：这个版本只从 OJ 拉清单和得分，不会替你提交代码、撤销提交或改分数。
- OJ 部署在校内网，只有连着校园网（或学校 VPN）才连得上。在家打开时它不会报错挡路，
  只是这次不显示 OJ 那几条，畅课照常。
- 登录凭据（`sessionid`）用 Windows DPAPI 加密存在 `%LOCALAPPDATA%\HomeworkDesk\data\oj_session.dat`，
  服务端会话约两周过期，到期后在登录框里重新输一次验证码就行。
- 新增 `oj_client.py`；`homework_server.py` 多了 `/api/oj/status`、`/api/oj/captcha`、
  `/api/oj/login`、`/api/oj/logout` 四个接口，`/api/homework` 的返回里多两个字段：
  `oj`（OJ 连接状态）和 `lmsAuth`（畅课未登录时非空，值为 `code`/`message`，
  前端据此显示登录入口而不是整页登录卡）。

## [1.5.2] - 2026-11-02

### Added

- **「已完成」入口，可以把误勾的作业恢复回来**。待办列表标题右侧多了一个
  「已完成 N」的虚线小按钮，点开是本机勾成完成的那批作业（标题 + 完成时间），
  每条右侧一个「恢复」：点一下就从记录里删掉、并重新拉一次待办，作业回到列表。
  - 顶上有关键词搜索框，只按标题/课程过滤，纯本地匹配。
  - 「全部恢复」按当前筛选结果批量撤销，执行前有一次确认。
  - 「重新读取」直接从 `state.json` 再读一遍，多个窗口互相同步用得上。
- 勾完之后那条 toast 改成提示「点错了可在『已完成』里恢复」，不再只说「仅从应用移除」。

### Changed

- 本机完成记录从「只能写、不能读」变成完整的增删查：`DataStore` 新增
  `completed_records()` / `unmark_completed()`，`AppContext` 转出
  `completed_records()` / `restore_completion()`。
- 恢复时顺手把待办缓存（`_todos_cache`）置空，否则 20 秒内重新拉列表还是被过滤过的旧数据，
  恢复的作业看起来「没回来」。

### API

- 新增 `GET /api/completed` → `{items: [{id, title, completedAt}], completionMode}`
- 新增 `POST /api/homework/{id}/uncomplete` → 有记录时 200，没有记录时 404

### Notes

- 恢复只动本机记录，不会在 LMS 上产生任何操作；如果平台已经不再把这条作业列进待办
  （截止很久、被老师收回等），主界面不会重新出现它，但记录确实是删掉了。

## [1.5.1] - 2026-10-29

### Added

- **可以直接交作业了**。作业内容展开后多一块「提交作业」，能力与网页端对齐：
  选文件（可多选）/ 选文件夹（保留目录层级）、写说明、存草稿、提交、撤回，以及交完之后
  在卡片上看到「已提交 · 时间」和文件清单。
- **打包成 ZIP 再提交**。勾上之后选中的文件先打成一个压缩包再传，包名可以自己填
  （默认用作业标题，非法字符会清掉、补 `.zip`、超长截断）。两件事靠它解决：
  平台对部分后缀直接拦（`.exe`、`.py` 之类），打包成 `.zip` 就能过；一次交整个工程目录
  时也不必几十个文件逐个传。压缩包里自动附一份 `提交说明.txt`。
- 提交前**二次确认**弹窗：写明课程、作业、文件（或压缩包名与内含数量）、是否说明、
  是否是再次提交，点「确定提交」才真的发出去。

### Changed

- 「勾选完成」与「提交作业」是两件事，README/界面文案都改成明确区分：
  勾选只在本机隐藏，不会产生任何提交。
- 服务端 `_api_get_json` 收敛成通用的 `_api_json(method, url, payload)`，交作业需要的
  POST/PUT 与错误信息解析（`message`、`errors` 第一项）都走同一套。

### Notes

- 提交走的是网页端同一批接口：`POST /api/course/activities/{id}/submissions`
  （草稿同一个接口 `is_draft=true`，改草稿时 `PUT` + `submission_id`）、
  `PUT /api/submissions/{id}/retract`、上传三步 `POST /api/uploads` → `PUT upload_url`
  → S3 再打 `/internal-api/upload/callback/{id}`。详见 HANDOVER 3.6。
- 平台把附件存七牛云（`storage_type=QINIU`）的情况没有实现，会直接提示到网页交；
  在线答题型作业不支持（当前 23 条作业全是 `file_upload`）。

## [1.4.3] - 2026-10-29

### Added

- **系统要求变成硬门槛**。界面靠 WebView2 渲染，而 Edge/WebView2 早已停止支持 Win7/8.1，
  之前没有任何拦截：Win7 用户能一路装完，然后双击没反应。现在两道检查：
  - 安装程序加 `MinVersion=10.0.17763`（Windows 10 1809），低版本直接提示并不予安装；
  - 启动时读注册表确认 WebView2 Runtime（同时查 HKLM、WOW6432Node、HKCU 三处），
    缺失就弹原生对话框说明原因，点「是」直接打开微软官方下载页。
- README 补「系统要求」一节，把 64 位 / Windows 10 1809+ / WebView2 三条依赖写清楚。

## [1.4.2] - 2026-10-29

### Fixed

- **附件改成原样下载**：1.4.1 走的是 `/api/uploads/document/{id}/url`，这条接口只给平台转码后的
  PDF，于是 docx 存下来变成同名 `.pdf`。现在先用 `/api/uploads/{id}/url` 换**原文件**直链，
  下载下来的文件名、扩展名、字节数都和老师上传的完全一致；原文件接口不可用时才退回 PDF 兜底。
  实测 12 个附件（docx/doc/pptx/ppt/zip/md/pdf）全部原样拿到，字节数与平台记录的 `size` 逐一相等。

## [1.4.1] - 2026-10-29

### Added

- **直接看作业内容**：每张卡片新增「查看作业内容」，展开即可看到老师在深大优课里写的正文，
  段落、换行、列表、表格、图片都保留（上游 HTML 先按白名单清洗，脚本/行内样式/iframe 全部丢弃）。
  列表接口 `/api/todos` 本身只有标题和截止时间，正文是通过 `/api/activities/{id}` 按条取的，
  取到后缓存 10 分钟，只有手动刷新才重新拉。
- **附件下载到桌面**：展开内容后列出该作业的全部附件（文件名 + 大小），点单个附件直接存到桌面；
  多个附件时右上角有「全部下载」。文件落到当前用户桌面（跟随 OneDrive 重定向），重名自动加
  ` (1)`、` (2)`，**绝不覆盖桌面上已有文件**。
- 附件数量会在列表加载后后台预取，卡片上直接显示「N 个附件」，点开时不用等；
  同时只跑两个预取请求，失败静默，点开时再试一次。
- 展开状态记在 `state.openDetails` 里，列表自动重绘（完成勾选、定时刷新）后仍然保持展开；
  正在看正文时暂停 28 秒一次的自动刷新，避免读到一半卡片被重画。

### Changed

- 卡片里原来那行「备注」不再展示。上游待办接口本来就不返回备注，这一行永远是空的，
  现在由正式正文替代。

### Fixed

- **下载类 POST 的请求体没有被读取**：`/attachments/*/download` 不看 body，但 `BaseHTTPRequestHandler`
  也不会自动丢弃它，残留的 2 个字节会污染同一条 keep-alive 连接，导致紧接着的下一个请求被解析成
  `{}POST ...` 并返回 501。现在所有下载接口先调 `_discard_body()` 读掉请求体。

### 说明

- 深大优课对 Office 文档（doc/docx/ppt/pptx）只提供转好的 **PDF** 直链，所以这类附件下载下来是 PDF，
  文件名会自动改成 `.pdf` 并在提示里说明；zip、图片、md 等则是原文件。
- 附件上限 300 MB（上游 63 MB 的数据集包实测可下）。

## [1.3.1] - 2026-10-28

### Added

- **外观主题**：主界面右上角新增「主题」按钮（调色板图标），弹出主题面板即时预览，
  目前内置三套：
  - **暖色**（米白 + 墨绿，1.2.x 的默认观感，默认选中）
  - **亮色**（中性冷白，白天/玻璃屏幕下更清爽）
  - **深色**（深石板底 + 亮薄荷绿，夜里护眼）
- **导入自定义主题**：面板里可以粘贴主题 JSON 或选择 `.json` 文件导入；只写 3 个核心
  变量也能用，其余派生色（hover / 描边 / 强调文字 / 悬浮球配色）按 `scheme` 自动推导。
  「复制当前主题 JSON」可以把当前主题导出成模板，改几个色号就是一套新主题。
- **自定义主题管理**：导入后出现在面板里，右上角垃圾桶图标点一次变「删除？」，再点一次

- **悬浮球跟随主题**：球体渐变、角标、概览卡片玻璃层、文字、右键菜单全部按主题绘制
  （`themes.ball_palette()` 把主题推导成 34 个 ARGB 角色）。切换主题立即重绘，不用重启。

### Changed

- 主界面样式表里 110 处写死的颜色和 64 处 `rgba()` 全部归并成 CSS 令牌（`--bg`、
  `--surface`、`--ink*`、`--green*`、`--red*`、`--orange*`、`--line*`、`--gloss`、

  不注入任意 CSS，自定义主题再怎么调也不会把可读性搞崩。
- 首屏防闪色：主题令牌由服务端在返回 HTML 时注入 `<style id="theme-vars">`，

- 强调文字改用专用令牌（`--accent-ink` / `--danger-ink` / `--warn-ink`），
  深色主题下「已逾期 / 紧急」这类红绿文字不再糊在深底上看不见。
- 主题与自定义主题分别存在 `prefs.json` 的 `theme` 字段与 `themes.json` 的
  `custom` 数组里；`prefs` 里的主题 id 失效时（主题被删、手改过文件）自动退回
  默认暖色并纠正 `prefs`，不会出现「一个都没选中」的空状态。

## [1.2.3] - 2026-10-28

### Fixed

- **悬浮球左右键突然全部失灵、也拖不动**（1.2.2 引入的严重回归）。根因是
  `ctypes.windll` 进程级共享：`ball_window.py` 和 `shrink_anim.py` 各自声明了
  `kernel32.SetWaitableTimer` 的原型，且都写成 `POINTER(自己的 _LARGE_INTEGER)`。
  `desktop_app.py` 先 import `ball_window`、后 import `shrink_anim`，后者的声明
  把前者的覆盖掉 —— 悬浮球的 60 fps 动画时钟线程第一帧就抛
  `ctypes.ArgumentError: expected LP__LARGE_INTEGER ...` 并退出，
  `_animating` 永远停在 `True`，之后 `expand()` / `collapse()` 全被
  `if self._animating: return` 静默吞掉，表现就是点左键不展开、点右键不弹菜单。
  现在两处原型统一声明成 `c_void_p`，调用处显式 `cast(byref(...), c_void_p)`。
  （同一类问题 1.2.2 已经踩过 `CreateDIBSection` 和 `UpdateLayeredWindow`，这次是
  第三个函数，已在代码注释里写清楚原因。）
- **动画永远不会卡死**：`AnimClock` 一旦建不出高精度定时器或线程异常，就自动退回
  `SetTimer(10)` 继续出帧；另外 `expand` / `open_menu` / `collapse` 入口都有
  「动画超时（时长 + 0.6 s）未收尾就强制复位」的自愈逻辑。任何时钟故障都只会
  让动画降级，不会再让悬浮球彻底失聪。
- **第一次收起到托盘时的气泡提示不显示**：`ShowBalloonTip` 的第 4 个参数是
  `ToolTipIcon` 枚举，原来传 `1`，pythonnet 3 拒绝 int→enum 隐式转换，
  日志里一直是 `int can not be converted to Enum`。改成 `ToolTipIcon.Info`。

### Changed

- 调试开关 `HOMEWORK_DESK_AUTOSHOW_FLOAT=1` 改为走「关闭主窗口 → 吸进悬浮球」的
  完整路径（原先只是显示悬浮球），这样一条开关就能回归收缩动画和球的交互。

## [1.2.2] - 2026-10-28

### Fixed

- **主窗口标题栏拖不动**：原来靠 pywebview 注入的 JS 拖动（每次 mousemove 发一次
  IPC 调 `Window.move`，坐标用 `screenX - clientX` 推算），按住后窗口经常纹丝不动。
  改成 `DesktopBridge.window_drag()`：mousedown 时记下「光标 − 窗口原点」的偏移，
  之后按 60 fps 轮询全局光标、用 `SetWindowPos` 把窗口挪到「光标 − 偏移」，一次 IPC
  走完整个拖动；绝对位移，DPI 缩放下也不会累积误差。双击标题栏最大化保持不变。
- 顺手记下一条：`WM_NCLBUTTONDOWN + HTCAPTION` 在这类 frameless 窗口上不会启动系统
  移动循环（实测窗口完全不动），`ReleaseCapture()` 也只对本线程的鼠标捕获有效，
  所以那条老路走不通。

### Changed

- **收起主窗口改成「吸进悬浮球」**：不再只是页面淡出，而是先抓一帧主窗口画面，
  用分层窗口（`WS_EX_LAYERED` + `UpdateLayeredWindow`）按 `easeInQuad` 缩到悬浮球
  的位置并淡出，280 ms、60 fps；第一帧盖上去之后才隐藏真窗口，中间不会闪桌面。
  抓帧优先用 `PrintWindow(PW_RENDERFULLCONTENT)`（被遮挡或跑到屏幕外也能抓），
  失败再退回屏幕截图；都失败就直接切换，功能不受影响。新模块：`shrink_anim.py`。
- 两个模块都会声明 `gdi32.CreateDIBSection` / `user32.UpdateLayeredWindow` 的原型，
  而 `ctypes.windll` 是进程级共享的：结构体类型各写各的会互相覆盖，导致悬浮球
  创建绘图表面时直接 `TypeError`。现在统一声明成 `c_void_p`，调用处显式 `cast`。
